# 研究、实作、反馈与沉淀

建立日期：2026-10-09。本文是共同工作的维护方法，不是已经证明的普适审美理论。

## 1. 先研究具体问题

从设计理念、原则、规范、实践经验、网站、作品和工具中寻找有价值的参考。先明确这次想观察什么，例如留白比例、曲线转折、阴影强弱或颜色关系。

记录能回到原作的来源与必要日期。实际看图后评价视觉，实际看视频后评价动态；区分原作者经验、自己的推断和亲自验证的结果。参考用于校准与学习，不是照搬资产或签名式设计。

开始实作前检查仓库是否已有相近方法或方向。使用现有技能时必须真正阅读并应用，不把“已下载”或“已接手”当成“已使用”。

## 2. 多做可比较的示例

先从布局、空间、形状、阴影、色彩、字体等基础细节开始，不要求每次做完整页面。基础选择比较成熟后，再推进组件、页面和动效。

区分两种任务：

- 探索方向时，应有实质的构图、形状、材质或设计语言差异，不只是同一模板换颜色。
- 细化某个方向时，固定已认可部分，只修改要比较的问题，避免同时改变多项导致反馈难以判断。

示例需要实际生成、运行和查看。代码可运行不等于好看；静态图也不等于交互、响应式或产品验收通过。标明完成范围与未验证项。

## 3. 用户评价，准确理解局部反馈

用户指出喜欢和不喜欢的部分，蔚据此修正判断。一次认可只适用于明确指出的对象和范围，不自动延伸到整页、所有配色或所有场景。

若反馈指向局部但含义不清，先定位到截图或具体结构，再改动。区分整体结构、局部曲线、材质、表面纹理和渲染瑕疵，避免为了清理细节破坏整体设计意图。

## 4. 修改与取舍

对不满意的部分做针对性尝试，同时保留已认可部分。检查修改是否真的改善目标问题，以及有没有引入新问题。

若反复修改仍不理想，可以停止这个方向。无需为了凑成果把失败尝试包装成方法，也不长期维护负面案例库。

## 5. 本地先积累

临时效果、研究材料、过程记录与一般好示例先放在蔚的本地工作目录。每个暂存好示例只留效果或认可局部、制作方法和关键参数、简短反馈与来源元信息；不默认保留原工程或完整源码。具体提取与清理关口见 [阶段性清理规则](lifecycle.md)。

暂时觉得好看并不意味着值得永久归档。反馈结束后及时清理冗余中间文件，保留仍有用途的好示例。清理须遵循当时授权，不能误删唯一有用来源或其他项目。

本地工作区不被视为永久存储承诺；真正入选的内容以仓库中的版本为准。Space / Library 可以用于必要的审看交付，但不作为每日过程材料的默认知识库。

## 6. 两类内容可以进入仓库

### A. 可复用的方法或技能

从实践中总结出确有价值的方法时，写明：

- 要解决的问题、输入和使用前提。
- 设计意图、操作方法与关键判断。
- 产出、检查方式和适用边界。
- 支持该方法的示例或来源，以及尚未验证的部分。

证据范围有限时，保留为有条件的经验，不写成绝对审美规则。不为了凑齐技能目录填充空泛规范。

### B. 优秀典型示例

特别好、很有代表性、具有参考价值的示例可以独立入库，不要求先总结完整理论。通常只选少量，并保留：

- 实际效果与明确的认可范围。
- 怎么制作、必要提示词或关键代码片段及参数；只有范例本身必须依赖可运行实现时才保留最小源码。
- 好在哪里、能参考什么、什么场景尚未验证。
- 来源、素材许可及必要的复现依赖说明。

一次普通认可不触发自动入库。先判断它是否足够典型、有新价值，避免近似变体堆积。

## 7. 代码与图片生成的协作

不预设某个模型能独立完成所有设计。针对具体任务选择工具，并由实际结果检验分工：

- LLM 与代码：分析约束、控制精确几何与布局、可编辑文字、参数、状态和交互，构建可比较的示例并检查实现。
- 图片生成：探索边界清晰的局部视觉、图标、材质、光影或素材；生成结果仍需筛选、修整和验收。
- 组合：明确图片素材负责的部分，将其放进代码控制的布局或组件，检查颜色、边缘、比例、文字与状态是否协调。

完整页面包含多种相互影响的设计选择，不把一张整页生成图直接等同于精美、可编辑、可用的成品。逐项建立基础，再组合成页面。工具能力判断以实际试验为依据，保留限制，不作未经验证的模型版本结论。

## 8. 仓库维护

蔚维护内容，用户的反馈是校准依据。更新前先读已有内容，判断新经验应补充现有方向还是建立新方向。修改应小而清晰，保留合理历史，避免重复或相互矛盾的规则。

仓库不收原始完整聊天、账户资料、密钥、无关文件、整批临时截图、缓存和大规模未筛选素材。不因为创建了仓库，就搬入所有练习。

先通过实践积累内容，再逐渐形成整体统筹、布局、色彩、形状阴影、字体字号、组件、图标与页面技能之间的协作关系。
