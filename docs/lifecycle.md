# 阶段性提取、入库与清理

目的：持续研究和大量实作，同时避免原始材料、源码与临时示例不断占用空间。以阶段完成的证据触发清理，不因日期较旧就盲删。

## 一、轻量状态记录

每批本地工作维护一份简短索引，记录批次、示例编号、当前阶段、认可范围、提取文件位置、仓库提交和清理状态。不在索引里复制完整聊天或长期记录负面评价。

阶段顺序：待评价 → 待修改或已评价 → 已提取 → 待总结 → 已入库或继续暂存 → 已清理。

状态不同于质量：已评价不等于认可；已提取不等于已总结出理论；已入库必须有远端可读取的提交证据。失败或中断只能记失败，不提前移动状态。

## 二、第一道关口：评价结束，提取好示例

只提取用户认可的效果或具体局部，不自动收整张页面。每个本地好示例保留一份最小参考记录：

1. 效果图、局部截图或必要短视频，标明认可范围。
2. 怎么设计：核心构成、操作步骤、关键参数、提示词或必要代码片段，工具与版本仅在确知时记录。
3. 为什么值得参考、适用条件和未验证事项。
4. 原始素材元信息：来源永久链接、作者、日期、素材名称或版本、许可及使用限制。自行生成则注明生成方式与关键输入。

不要求保存整个工程来追求完整复现。目标是以后能理解、参考或选入仓库。仅当素材本身不可替代且合法使用、没有它无法理解效果时，保留最小必要素材，并写明原因。

### 清理前检查

- 所有要保留的认可局部都已提取，文件实际可打开，记录可理解。
- 改到一半或尚未评价的项目没有被算作已结束。
- 仍在使用的示例不依赖待删除的文件。
- 明确列出本批可清理路径与预估大小，不跨批次扩大范围。

检查通过后，可清理这批原始调研下载、过程截图、冗余变体、完整代码/源工程、构建输出与缓存。不保留失败样例全集；若还需要下一轮修改，保留当前最小工作集直到该轮结束。

## 三、第二道关口：阶段总结，内容入库

定期回看本地已提取的好示例，寻找共同规律、适用边界及不同场景中的变化。能总结的方法补充现有技能；确有新方向时再建立新技能。特别优秀典型的示例可单独入库，不以形成完整理论为前提。

每次总结都允许得出“目前不足以提炼”的结论，不为清理磁盘制造技能或强行入库。

提交后必须核对：

- 远端实际存在目标提交，文档、图片及必要链接可读取。
- 入库内容覆盖需要保留的知识和认可效果，无遗漏或错误替换。
- 经典示例只保留必要资产；需要可运行示例时才保留最小实现和依赖说明。
- 本地索引记录仓库路径与提交，不依赖临时附件作为唯一入口。

确认完成后，可清理已被仓库承接的本地临时参考、重复副本和阶段工作包。只清理已完成转存的部分；未入库但仍有参考价值的示例继续轻量暂存，定期重新判断，不无限复制。

## 四、让规则持续执行

- 每次用户完成一批评价后，检查第一道关口，提取可留部分并准备清理清单。
- 每天开始整理研究时，顺带检查上次未完成的提取、待清理项与磁盘用量；无需每天重新扫描所有文件。
- 每周在既有整理时段回看已积累的好示例；初始安排为北京时间周日早上的整理阶段。没有足够材料就不产出空总结。
- 完成一次仓库更新后，检查第二道关口，不把“已上传”直接等同于“已核验”。
- 如空间紧张，优先检查已提取、已入库的重复文件，不删除唯一未评审内容。

## 五、删除边界

此流程不自动授予永久删除权限。可恢复清理在用户授权范围内执行；不可恢复删除、清空回收站前，列出具体范围与后果并获得当次确认。没有确认就保留待清理状态，不能宣称已释放空间。

不删除其他项目、账户或浏览器配置，不清理密钥目录，不把来源不明文件当临时文件。报告时区分“已提取”“已移回收站”和“磁盘实际释放”。
