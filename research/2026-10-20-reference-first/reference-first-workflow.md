# 参考先行：让 AI 做出专业界面的工作流（2026-10-20 实践记录）

## 1. 为什么 v1–v3 都失败
- **现象**：v1（暖纸 + 朱红）、v2（Geist + 蓝）、v3 三个方向（方法档案 / 半透明光片 / 色块与器物），用户评价都是"不像专业设计师做的、杂乱、形状不好看"。最后一次反馈是"布局、结构、形状、大小、字号、颜色、阴影都不行"。
- **原因**：每一版都是 Agent **自创风格**，再按规则自检。规则能挡住明显错误，但给不出专业水准：对齐线不统一、字号档位太多、灰阶和强调色凭感觉、阴影和圆角各自为政。换模型也一样（"看来所有模型都是一样的"）。
- **转折**：先找真实的专业作品让用户挑，**量出数值再照着做**。第一版照 Linear 做的 HTML 就明显好于前三版；再进 Figma 用变量和组件重建，用户评价"比 ui-design-skills 里任何一个都专业"。

## 2. 八步流程
1. **收集真实参考，让用户挑**：先给 6 个风格明显不同的真实网站（桌面 + 手机首屏）。用户选了 Linear，后来补充 macOS 的 Finder、Mail、HIG 窗口结构图和 Bear。没被认可的参考不进入后续步骤。
2. **量数值，并标注来源**：网页用 Playwright / headless Chrome 读 `getComputedStyle`，标 [DOM]；截图逐像素量，标 [量]（估算）；官方文档标 [官方]，社区数据标 [社区]，查不到的标 [未知]，不乱填。
3. **拆解**：分析每个参考的布局骨架（对齐线、栏宽比例）、信息层级（字号、字重、颜色几级）、表面（底色差几档、线还是阴影、圆角怎么嵌套），以及内容手法（真实数据、裁切、浮层）。
4. **定规范（Foundations）**：
   - 颜色分两层：原始色（primitives）和语义色（semantic）。表面 6 档灰，**文字 4 级用同一色相**，**只有一个强调色**，状态色只出现在产品界面的小圆点里
   - 字号最多 5 档（桌面 56 / 40 / 20 / 15 / 13），标题字重 500
   - 圆角 12 / 8 / 6 / 4，按钮和标签用胶囊
   - 间距用 4 的倍数（2–128）
   - 区块上下留白按视口缩放：桌面 96–128，手机 48–64
5. **做组件和变体**：按钮、侧栏行、列表行、工具栏组、输入框，每个都有状态变体，填充、描边、圆角、间距全部绑定变量。
6. **画对齐栅格**：桌面 1440 宽，12 栏，文字列 x=80…1360；手机 390 宽，4 栏，左右边距 24。
7. **逐区块拼页面**：桌面首屏放应用窗口，三栏布局（侧栏约 17–20% / 列表 / 详情），用真实数据；手机一次只显示一栏，点进去再到下一层，**不缩小三栏**。
8. **截图审查，多轮修复**：和参考在同一位置并排比，问题写成"位置 / 现状 / 目标值"，修完再截图复查。本次 HTML 做了 3 轮，Figma 做了 2 轮。

## 3. 十条规则（含用户补充）
1. 先定一组对齐线，所有区块左右边缘都压线，不许各区自定边距。
2. 字号最多 5 档，标题字重 500–600，字距收紧（英文 ≈−0.02em，中文见第 4 节）。
3. 文字用同一色相分 3–4 级明度，不靠换颜色分层级。
4. 一屏只用一种强调色，只给主按钮、选中项、焦点和链接。
5. 相邻区域只差一两档灰，只在两栏之间用一条约 1px、8–10% 不透明度的细线。
6. 圆角外大内小（12 → 8 → 6 → 4），大按钮用胶囊。
7. 阴影只给浮在上面的层；平铺的卡片和列表用细线分开。
8. 展示产品就放有真实感的界面，用真实的编号、人名、时间和数字，不用占位文字或抽象插画。
9. 应用界面用"侧栏、列表、详情"三栏，侧栏约占 17–20%，工具栏按功能成组。**三栏只用于桌面；手机一次显示一栏，逐层进入。**
10. 留白多于内容。区块上下留白**随视口宽高缩放**（桌面 96–128，手机 48–64），正文一行不超过约 70 个字符。

## 4. 中文排版调整（与 Linear 原值的差异）
1. 标题字距 −0.022em → −0.012~−0.015em：方块字本身没有字间空隙，压太紧会让笔画相碰。
2. 标题行高 1.0 → 1.1–1.17：中文没有上下伸部，行高 1.0 时两行几乎粘在一起。
3. 正文中文字距设为 0（Linear 的 −0.011em 是为拉丁字母设计的）。
4. 字体回退：PingFang SC → Noto Sans SC。Figma 里没有 PingFang，统一用 Noto Sans SC（Regular / Medium）。
5. 等宽和大写标签只放英文与编号（FIG 0.1、STEP 01、UI-142），中文不做大写或等宽。
6. Linear 的 64 / 48 照搬到中文会显得重，调成 56 / 40 更合适。

## 6. 与仓库原有方法的关系
仓库原本的金标准是"先决定美感由什么承载，再让 Web 与 GPT Image 各自独立探索"。本次实践说明：**Agent 的基础功（对齐、字号、灰阶、阴影）还没达到专业水准时，独立探索只会产出"像 AI 做的"结果。**所以先用一个用户认可的专业参考做校准，做到"看起来专业"，再在这个基线上探索自己的表达。这是对原有第 1–4 阶段的补充，不是替代。
